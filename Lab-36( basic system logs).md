## What Are System Logs?

Linux systems continuously record information about system activity and events.

These records are called *logs*.

Logs can contain information about:

- System services starting and stopping
- Authentication and login-related activity
- System processes
- Network and system events
- Errors and warnings
- Scheduled jobs
- Package management activity

System logs are commonly stored inside:

```bash
/var/log
 The /var/log directory can be thought of as a collection of records generated by different parts of the Linux system.
Navigating to /var/log
I navigated to the system log directory using:
cd /var/log
I verified my location using:
pwd
The output confirmed:
/var/log
I then listed the available log files using:
ls
Important Log Files
Different log files contain different types of information.
Some common examples include:
syslog       → General system and service messages
auth.log     → Authentication-related activity
kern.log     → Kernel-related messages
dpkg.log     → Package management activity
The exact files available can vary depending on the Linux distribution and environment.
Understanding a Log Entry
I examined recent entries from /var/log/syslog using:
tail -n 5 /var/log/syslog
Example entries showed events such as:
Started ssh.service OpenBSD Secure Shell server.
Job 'cron.weekly' started
Job 'cron.weekly' terminated
A typical log entry can contain:
Date/Time → Host → Process/Service → Message
For example:
2026-08-17T10:22:39... ip-172-31-10-254 systemd[1]: Started ssh.service
Understanding the Parts
Date and time → when the event occurred.
Host → the machine that generated the log entry.
Process/service → the component involved in the event.
Message → what happened.
The host information does not necessarily identify the person who performed an action. Additional authentication or audit logs may be required to determine the user involved.
Using tail
The tail command displays the end of a file.
I used:
tail -n 5 /var/log/syslog
This displays the last five lines of the system log.
The -n 5 option specifies that five lines should be displayed.
Monitoring Logs in Real Time
I learned that tail -f can continuously monitor a log file.
tail -f /var/log/syslog
The -f option means follow.
Instead of displaying the current end of the file and stopping, tail -f continues running and displays new entries as they are added to the log.
I stopped real-time monitoring using:
Ctrl + C
Combining tail with grep
I combined concepts from previous labs by using grep with tail.
tail -f /var/log/syslog | grep "ssh"
This means:
tail -f
↓
Continuously monitor the log

|
↓
grep "ssh"
↓
Only display new entries containing "ssh"
At first, no output appeared because no new SSH-related event had occurred.
I then generated an SSH event by restarting the SSH service:
sudo systemctl restart ssh
The monitoring terminal displayed new SSH-related entries.
The output showed events such as:
Stopping ssh.service
ssh.service: Deactivated successfully
Stopped ssh.service
Starting ssh.service
Started ssh.service
This demonstrated that the log was being monitored in real time and that grep was filtering the results.

Practical Use
System logs are important in Linux administration and cybersecurity.
Instead of manually reading thousands of log entries, we can search and filter them.
For example:
grep -i "error" /var/log/syslog
can search for messages containing error.
Recent entries can be viewed with:
tail -n 20 /var/log/syslog
Specific events can be monitored in real time with:
tail -f /var/log/syslog | grep "ssh"
This can help administrators and security professionals investigate system activity, troubleshoot problems, and monitor services.
```
